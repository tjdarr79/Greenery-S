COMMIT MESSAGE
--------------
Home Assistant add-on: run the bridge on HA itself and retire the PC

Packages the bridge as an HA add-on installable from this repo as a custom
add-on repository, replacing the separate always-on Windows PC.

Supervisor already knows the MQTT broker's address and credentials, so the
add-on reads them with bashio::services and the operator types nothing. That
removes the most failure-prone step in the project - the homeassistant.local
trap and wrong MQTT credentials - which the Windows installer needs a third of
its code to defend against.

Also adds MQTT_PORT and LOG_LEVEL as environment-configurable in the bridge,
and a byte-for-byte drift check in verify-repo.py between the root
farm_bridge.py and the copy inside the add-on's Docker build context.

Not build-tested: no Docker daemon was available and HA Green is aarch64.
Manifest, shell and YAML are validated; the image build is unproven until
someone installs it.

AFTER PUSHING - INSTALL THE ADD-ON
----------------------------------
1. Settings > Add-ons > Add-on Store > three-dot menu > Repositories
2. Add:  https://github.com/tjdarr79/Greenery-S
3. Install "Greenery S Farm Bridge"
4. Before starting it, STOP the Windows bridge. Two bridges publishing the same
   MQTT topics will fight each other.
       On the farm PC:  schtasks /end /tn "Greenery S Farm Bridge"
       and set it disabled, or run UNINSTALL-FARM-BRIDGE.bat
5. Start the add-on. Watch its Log tab for "MQTT connected".
6. Check Settings > Devices & Services > MQTT > Greenery S Farm still shows
   ~54 entities and the values are updating.
7. Once it has run a day, the Windows PC can be shut off.

If the image fails to build, send the add-on's build log and it can be fixed.
